# NPC: статус реализации

## Сделано

- Этап сдачи проверен в Chrome: три профессии, полный рабочий день, шторм через кнопку интерфейса, укрытие и продолжение, сохранение/загрузка в пути без потери позиции и паузы.
- Замерены 0/50/100/300 NPC. Детали моделей объединены: для 300 NPC draw calls снизились с 5949 до 4173; средний кадр в программном WebGL — с 36,27 до 25,95 мс. Отчёт и воспроизведение: `NPC_ACCEPTANCE.md`.

- Граф строится из общей схемы улиц: обе стороны всех тротуаров и все 300 размеченных переходов. Дублирующее светлое покрытие убрано; A* выбирает кратчайший доступный путь. Замер расчёта: 50 маршрутов ~21 мс, 300 ~415 мс; из кеша <0,1 мс. Подробнее: `PEDESTRIAN_ROUTING.md` (это не замер FPS).

- Походы на работу включены только для 50 жителей домов первого сектора. Остальные 250 профилей остаются дома без назначения; старые сохранения переводятся на это правило.
- Выбранный житель отмечен небольшим значком над головой. Карточка показывает его модель с экипировкой, сектор, скорость ходьбы, профессию, назначение и текущие статусы.
- Интерфейс NPC переведён на английский; новые надписи интерфейса добавляются только на английском.

- Исправлена ходьба между серверными обновлениями: равномерная скорость по маршруту, масштабирование скоростью времени, выход из двери и завершение пути у входа. Расписание распределено по 26 минутам вместо шести групп; старые стандартные расписания обновляются при загрузке.

- Процедурная модель человека; экипировка инженера, электрика и учёного.
- Idle/walk, плавный поворот, привязка к рельефу.
- 300 постоянных профилей: ID, дом, профессия, рабочее здание, расписание.
- Цикл `HOME → WALK_TO_WORK → AT_WORK → WALK_HOME`; смены 08:00–08:25 → 16:00–16:25.
- Пауза, сохранение состояния и маршрута, восстановление в пути, миграция старых сохранений.
- Базовая реакция на шторм и блокировку сектора; причина ожидания в карточке.
- Список жителей, карточка назначения, приближение и слежение камерой; профили доступны внутри зданий.
- Остановка в заданное время и кнопка «Продолжить · 1 мин/с».
- Общий граф тротуаров и переходов с A*: соединения проверены на пересечение домов и зданий вдоль путей.
- В первом секторе добавлены мастерская и лаборатория с наружными входами; все 300 домов подключены к ним.
- Подсветка пути выбранного NPC, движение по изгибам маршрута и высотам дорожек.
- Закрытие перехода вызывает обход, закрытие входа — ожидание `no_path`; открытие возобновляет движение. Перекрытия сохраняются.

## Осталось

Обязательные пункты текущего этапа выполнены. При необходимости — повторить замер на видеокарте целевого компьютера (`NPC_BENCH_HARDWARE=1`).

**Ограничение:** мелкие декоративные объекты и взаимное избегание NPC не входят в модель препятствий. 100/300 NPC — синтетические нагрузочные сцены; в обычной симуляции работают только 50 жителей первого сектора.

## Проверка

Из каталога `world`:

```powershell
py hadleys_hope.py --port 8000 --data ./data
py -m unittest discover -s tests -p "test_*.py"
```

После перезапуска открыть `http://localhost:8000`, обновить Ctrl+F5. Выбрать «Pause at 07:30» → «Run until», выбрать жителя, затем «Resume · 1 min/s». Если время прошло, остановка назначается на следующие сутки. При `--data` сохранение выполняется автоматически и при штатном Ctrl+C.

Маршруты: M → Places → «Show work sector». Там же доступны «Close crossing» и «Close workshop entrance»; повторное нажатие открывает путь.

Последняя проверка серверного кода: **50 Python-тестов прошли, 1 POSIX-тест пропущен на Windows**. Проверки JS-модулей, анимации, постановки стопы и точного восстановления модели прошли. Полный браузерный сценарий и замер производительности описаны в `NPC_ACCEPTANCE.md`; снимки находятся в `test-results`.
