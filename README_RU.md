# Симуляция Hadley's Hope

[![English version](https://img.shields.io/badge/lang-EN-blue)](README.md)

Симуляция шахтёрского посёлка на LV-426 в одном файле: 300 умных домов в шести секторах,
реактор и электросеть, вода, интернет, канализация, мусор, дороги, шлагбаумы, инциденты,
ремонты и деньги. Физика домов на numpy, интерфейс в браузере на обычном canvas.

## Запуск локально

```
pip install numpy
python3 hadleys_hope.py
```

Открыть http://localhost:8000. Процесс работает на переднем плане и пишет лог в терминал,
Ctrl+C останавливает.

```
python3 hadleys_hope.py --port 8000 --speed 20 --seed 12345
python3 hadleys_hope.py --data ./data          # автосейв и история в ./data, продолжение после перезапуска
python3 hadleys_hope.py --data ./data --fresh  # начать заново, игнорируя сохранение
python3 hadleys_hope.py --headless 43200       # месяц без интерфейса, сводка в консоль
```

`--speed` это симулированных минут за реальную секунду (1 такт = 1 минута). Переменные окружения:
`PORT`, `DATA_DIR` (то же, что `--data`), `ADMIN_TOKEN` (если задан, инъекции и скорость доступны
только по ссылке `/?admin=TOKEN`, остальные только смотрят).

## Сохранение

С `--data` или `DATA_DIR` мир сохраняется в pickle каждые пять минут и при SIGTERM / Ctrl+C
и восстанавливается при следующем старте, так что захощенный посёлок живёт сквозь деплои.
Почасовые метрики, лог событий и месячные отчёты пишутся в `history.db` (sqlite) и отдаются
по `/history?hours=720`.

## Хостинг

### Railway (быстрее всего)

1. Залить эту папку в репозиторий на GitHub.
2. railway.app: New Project, Deploy from GitHub repo. Dockerfile подхватится сам.
3. В настройках сервиса: Networking, Generate Domain (публичная https-ссылка). Variables:
   `ADMIN_TOKEN=свой-секрет`, `DATA_DIR=/data`. Volumes: добавить том с путём `/data`.
4. Каждый пуш в `main` передеплоивает. Сохранённый мир на томе переживает перезапуск.

### Свой VPS и GitHub Actions

1. На чистом Ubuntu под root: `git clone` этого репозитория, `cd` в него и `sh deploy/server-setup.sh`.
   Скрипт создаёт пользователя, venv с numpy, systemd-сервис на порту 80, каталог данных и открывает
   порты 22 и 80 в ufw. Токен положить в `/opt/hadleys-hope/env`.
2. `systemctl start hadleys-hope`, смотреть через `journalctl -u hadleys-hope -f`.
3. В репозитории на GitHub добавить секреты `SSH_HOST`, `SSH_USER`, `SSH_KEY` (пользователь деплоя, которому
   разрешён `sudo systemctl restart hadleys-hope` и запись в `/opt/hadleys-hope/`). Дальше `.github/workflows/deploy.yml`
   на каждый пуш прогоняет smoke-тест, копирует файл и перезапускает сервис.
4. Https по желанию: направить домен на сервер, поставить Caddy и проксировать домен на порт 80 (или задать `PORT=8000` в юните и проксировать туда).

Vercel, Netlify и другие serverless-хостинги не подходят: симуляция это долгоживущий процесс
с состоянием в памяти, а они завершают процесс после каждого запроса.

## Что видно

Страница `/` это 3D: посёлок обёрнут на маленькую планету. Тянуть мышью, чтобы вращать, колесо
для зума, наведение на дом показывает детали, клик по строке сектора или кнопке «fly to»
перелетает камерой. Чекбоксы слоёв включают issue, дома без интернета, значки заряда ИБП,
обогреватели, потоки энергии и воды, пакеты, людей, ксеноморфов и подписи. three.js грузится
с jsdelivr; для автономной установки положить пакет `three` из npm в `vendor/three/` рядом со
скриптом (`npm pack three@0.160.0`, распаковать, переименовать `package` в `three`), он будет
отдаваться локально. Плоская карта осталась на `/flat`, для телефона она легче.

Карта слева:

- Комплекс реактора за городом: реактор с режимом, солнечная станция, водозавод (топит лёд теплом реактора), хранилище отходов, шахта. Магистраль идёт к подстанции в центре.
- Центр: подстанция, ИБП центра, узел связи, операционный центр, насосная и бак воды.
- Шесть секторов по 50 домов. Цвет дома это температура внутри, красная рамка нет питания, синяя рамка дом на ИБП сектора, жёлтая рамка лимит мощности, крест лопнувшие трубы. Наведение мышью показывает подробности по дому.
- Столбы с фонарями (светятся, когда горят), пролёты ЛЭП (бегущие штрихи, когда под напряжением), рядом кабель интернета, пакеты бегут от домов к центру и к радиовышке.
- Кольцевая дорога со шлагбаумом на каждой границе секторов (зелёный открыт, красный lockdown), мусорные баки у кольца, роверы: G мусоровоз, S говновоз, E инженеры, P сантехник.
- Красные ромбы ксеноморфы, маркеры «!» открытые issue.

Панель справа: время и скорость, кнопки инъекций, бюджеты колонии и секторов, баланс мощности и ступень сброса нагрузки, телеметрия реактора, таблица по секторам, открытые issue, лог событий, последний месячный отчёт.

## Инъекции

`break span` обрыв пролёта, `fell pole` падение столба, `xenomorphs` атака и lockdown сектора,
`storm` буран, `cut trunk` обрыв магистрали (весь посёлок на ИБП), `pump trip` отказ насоса
(RUNBACK и сброс нагрузки), `marines fire` попадание в теплообменник и SCRAM, `SCRAM`,
`break road` разрушение дороги, `+50k cr` перевод от корпорации.

## Модель коротко

- Время: 1 такт = 1 минута, месяц 30 дней. Погода: среднее минус 45, суточный ход, синоптический дрейф, бураны.
- Дома: одна тепловая зона, `C dT/dt = Q_heat + Q_internal - UA (T_in - T_out)`, четыре типа домов, электроотопление 3..4.5 кВт, термостат с целями комфорт / эко / антизамерзание в зависимости от ситуации с питанием. Трубы замерзают через 60 минут ниже нуля и лопаются ещё через 30.
- Реактор: 6 МВт брутто, 0.6 МВт на себя, мощность за уставкой 5 % в минуту, температура зоны с насосами и естественной циркуляцией, остаточное тепло после останова, режимы ONLINE / RUNBACK / SCRAM / COOLING / EMERGENCY / STARTING / CORE_DAMAGE. Повреждение зоны завершает прогон.
- Сеть: магистраль, подстанция, шесть линий, распредпункт в секторе, шесть столбов на сектор с пролётами, вводы домов. Упавший столб рвёт пролёты и кабель связи. Сброс нагрузки в восемь ступеней: подогрев дорог, заряд ИБП, лимит 2 кВт на дом, фонари, лимит 1 кВт, шахта на 50 %, шахта выкл, отключение секторов.
- ИБП: центральный (800 кВт·ч) и по одному на сектор (400 кВт·ч, 100 кВт).
- Вода: водозаводу нужны тепло реактора и питание, бак 500 м³, расход по домам.
- Интернет: шкаф в секторе с ИБП на 2 часа, кабель по столбам, центральный узел, радиовышка на своей линии.
- Канализация: аэрационная станция в каждом доме, ровер-говновоз, хранилища ила по секторам. Мусор: баки по секторам, мусоровоз, станция переработки у реактора. Санитарный индекс по секторам.
- Инциденты: погода (логистическая функция от ветра, льда и мороза), ксеноморфы, морпехи (стрельба по охлаждению при активном гнезде), вандалы, животные, роверы сбивают столбы в тёмных секторах, износ насосов.
- Ремонты: issue финансируются сначала сектором, потом колонией; роверы едут к цели по дороге (разбитые дороги и lockdown задерживают, бригады в тёмных секторах атакуют). Без денег ничего не чинится.
- Финансы: бюджеты секторов 10 000, колонии 100 000. Владельцы платят за свет и воду ежедневно, сборы и возмещение ремонтов ежемесячно; шахта зарабатывает колонии, пока запитана. Месячный отчёт по причинам расходов.

Все константы в `CFG` и `COSTS` в начале файла.

## Куда встаёт ВМ

Поведение дома живёт в `houses_decide()`. Это место, куда подключаются скомпилированные
`.hbc` и `libhopevm`: функция читает датчики (`h_t_in`, `h_power_ok`, `h_on_ups`,
`h_limit_w`, ...) и ставит актуаторы (`h_heater_on`, `h_valve_open`).
